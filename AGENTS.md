# Project Working Rules

## Problem Log

- Keep `actual problems.md` as the persistent project problem log, as requested
  by the user. Read it before reviews and relevant implementation work.
- Record significant bugs, gaps against the specification or agreed plan,
  demonstration limitations, and unresolved verification gaps discovered during
  work. Do not leave these findings only in chat.
- Distinguish reproduced bugs from hypotheses and unverified limitations.
  Include affected code, reproduction conditions, observed and expected behavior,
  priority, status, and closure criteria where applicable.
- Preserve existing IDs and avoid duplicate entries. After fixing an issue,
  update its status, date, and verification evidence; retain the closed entry.
- Logging an issue does not expand the authorized implementation scope.
